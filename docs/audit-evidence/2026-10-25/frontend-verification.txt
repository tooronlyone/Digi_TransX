Digi_TransX remaining frontend remediation — 25 October 2026

Final production frontend source was frozen before the checks below. Commands
ran from frontend-react. Rendered tests use fake fetch and geolocation/Leaflet
boundaries; no live account, external geocoder or payment provider was called.

Changes and exercised boundaries

- FE-005: chat history and composer state live in a keyed ThreadMessages
  instance. Both the whole chat and its requests belong to a verified account.
  Delayed A responses cannot appear in B, including A-to-B-to-A switches, media
  operations and late sends. A same-account outgoing send retains its original
  thread; changing accounts cancels dispatch. Polling skips an in-flight read
  instead of repeatedly aborting a slow initial response.
- FE-006: manual address edits clear both lat/lng and remove the old map pin.
  Forward/reverse geocoder results are aborted/invalidated on edit or teardown.
- FE-007: agreement calendar arithmetic uses ISO date fields and matches the
  backend's month-end/leap-year clamping. Today uses Asia/Karachi explicitly.
  Tests execute in Pakistan, UTC, New York and Auckland timezones. Clearing an
  input does not crash rendering; invalid dates/durations cannot finalize.
- FE-013: carts use dtx:parts-cart:v2:<verified-user-id>. The unowned v1 cart is
  ignored rather than assigned to whichever account signs in next. Owner-keyed
  pages reset address/phone/form state, ignore foreign events and late checkout
  results, and maintain separate memory fallback when persistence is denied.
- A checkout queued during Web Crypto/CSRF cannot run after account teardown.
  Every marketplace checkout sends X-DTX-Expected-User-Id in addition to CSRF
  and its stable Idempotency-Key; the backend requires/matches that owner before
  creating an order. Late CSRF responses cannot repopulate the cache after auth
  cleanup invalidates its generation.
- Truck registration no longer collects a visible Driver ID or manual driver
  name/CNIC as a substitute for consent. Configuration identity is read-only and
  excluded from posted form data. New-tab registration fetches CSRF as needed.
- A collapsible DriverAssignmentPanel is integrated into owned OrderTracking and
  agreement trip/history views. It reads the server-owned truck/source IDs,
  submits a real invitation, shows requested/accepted state, and offers one review
  only when the backend marks a completed assignment eligible. Incident reports
  are shown as investigating, without claiming an allegation is confirmed.
- Actual driver Trip Requests use CSRF and preserve conflict errors. A stale
  StrictMode read cannot restore the pre-acceptance invitation state.
- GPS controls require an accepted assignment, send its ID, preserve zero-valued
  coordinates/altitude, clear watch ID zero, ignore stopped callbacks, and stop
  tracking visibly when the backend rejects an inactive source assignment.
