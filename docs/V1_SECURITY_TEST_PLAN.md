# Digi_TransX V1 — Comprehensive Security Audit & Test Plan

**Scope:** Active Digi_TransX V1 application (Flask backend, PostgreSQL/Supabase database layer, React SPA).
**Excluded Deferred V2 Domains:** Agreemental, Pump Manager / Fuel Station / Fuel Credit / Vouchers, Shopkeeper / Truck Parts Marketplace / POS, AI Assistant (archived under `Future/`).
**Environment Rule:** All active exploitation and chaos/concurrency verification in this plan must execute **only** against isolated local/staging instances and disposable test databases (`TEST_SUPABASE_DB_URL` on loopback). Never run destructive security payloads against production or shared Supabase projects.

## Detailed Test Execution Protocol (By Domain)

### A. Database & Financial Integrity Verification (PostgreSQL)
1. **Constraint & Trigger Penetration Checks (Negative Testing):**
   - Attempt cross-user `wallet_transactions` insertion (`wallet_id` owned by User A, `user_id` of User B) → must raise `ForeignKeyViolation` (`wallet_transactions_wallet_owner_fk`).
   - Attempt `'NaN'::numeric`, `'Infinity'::numeric`, `'-Infinity'::numeric`, `0`, or `1e15` insertions into `payments`, `wallets`, `wallet_transactions`, `wallet_withdrawal_requests`, `freight_settlements`, `freight_settlement_resolutions`, `security_reserves`, `driver_fuel_logs` → must raise `CheckViolation`.
   - Attempt `payments` insertion with `shipment_id = NULL`, `bid_price = 0` (`status='held'`), or mismatched `(trip_id, shipment_id, client_user_id, transporter_user_id)` → must raise `NotNullViolation` / `CheckViolation` / `ForeignKeyViolation`.
   - Attempt `UPDATE` or `DELETE` on `wallet_transactions`, `freight_settlement_resolutions`, `security_reserve_entries`, and settled/versioned `payments` → must raise `CheckViolation` (`23514`) or exception.
   - Attempt `UPDATE` on `payments` regressing terminal status `'released'` or `'refunded'` back to `'held'`/`'processing'` → must reject.
   - Attempt `INSERT INTO freight_settlement_resolutions` by a non-admin user, against a non-disputed settlement, against a wrong dispute, or with `client_refund_amount + transporter_release_amount != tranche2_amount` → must raise `CheckViolation` (`23514`).
   - Attempt committing an underbacked `security_reserves` increase (`reserve.balance > wallet.locked_balance` or `> wallet.minimum_required`) → must abort at `COMMIT` via deferred constraint trigger `trg_reconcile_security_reserve`.
   - Verify `driver_fuel_logs` POST/GET does not insert/update `wallets`, `wallet_transactions`, `payments`, `freight_settlements`, or `security_reserves`.
2. **RLS & Role Isolation Checks:**
   - Execute queries as PostgreSQL roles `anon` and `authenticated` (with mocked `request.jwt.claim.sub`) against all private operational and financial tables (`users`, `wallets`, `wallet_transactions`, `payments`, `freight_settlements`, `delivery_otp_challenges`, `driver_fuel_logs`, `vehicles`) confirming zero unauthorized reads or writes even after accidental `GRANT` simulation.
3. **Concurrency & Double-Spend Chaos Suite:**
   - Barrier-synchronized concurrent calls (`N >= 8` threads) to:
     - `perform_checkout` on the same order/wallet
     - `perform_wallet_topup` with identical and conflicting `Idempotency-Key`
     - `POST /api/wallet/withdraw-locked` with identical `Idempotency-Key` and insufficient balance for duplicate withdrawals
     - `open_delivery_dispute` vs `release_due_settlements` at expiry boundary
     - `issue_delivery_otp` + wrong OTP guesses + valid verification

### B. Web & API Application Security Checks (Local/Staging Harness Only)
1. **Authentication, Session & CSRF Verification:**
   - Verify every mutating V1 endpoint returns `403` without valid `X-CSRF-Token` matching session cookie.
   - Verify cookie attributes (`HttpOnly`, `SameSite=Lax`, `Secure=True` when `DIGITRANSX_ENVIRONMENT=production`).
   - Verify missing/placeholder `FLASK_SECRET_KEY` aborts boot when `DIGITRANSX_ENVIRONMENT` is not `local`/`test`.
   - Verify signup requests passing `legacy_role=admin|platform_admin|shopkeeper|fuel_station_manager` cannot gain privileged or deferred roles.
2. **IDOR / BOLA & Input Fuzzing Checklist:**
   - Parameterized matrix testing every ID-addressed route (`/api/orders/<id>/*`, `/api/payments/*`, `/api/trucks/<id>/*`, `/api/driver/*`, `/api/chat/threads/<id>/*`) across: owner, counterparty, unrelated same-role user, different-role user, unauthenticated user, admin.
   - Path-traversal probes (`..%2f`, `%2e%2e/`, null bytes, double extensions) against static serving (`serve_frontend`) and chat/truck file download routes.
3. **Pre-Production Header & Edge Controls (Sign-off Gate):**
   - Verify HTTP response headers at reverse proxy / Flask `@app.after_request`: `X-Frame-Options: DENY`, `Content-Security-Policy` (including `frame-ancestors 'none'`), `X-Content-Type-Options: nosniff`, `Strict-Transport-Security`, and `Referrer-Policy: strict-origin-when-cross-origin`.
   - Verify edge/application rate limiting (`429`) on `/auth/*`, checkout, and withdrawal endpoints under burst traffic before production cutover.

### C. Operational Ledger & Audit Readiness
- Schedule/run `py -3 -m scripts.reconcile_business_rules` in `READ ONLY` transaction mode after E2E scenarios; assert `'consistent': True` with zero entries across all 6 checks (`unbalanced_journals`, `freight_split_mismatches`, `underbacked_security_reserves`, `wallet_transaction_owner_mismatches`, `security_reserve_entry_mismatches`, `settlement_resolution_mismatches`).
- Inspect structured `security_events` & `business_audit_events` logs ensuring secrets, MPINs, OTP codes, full PANs, and session tokens never appear in logs or payloads.
